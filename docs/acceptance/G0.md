# G0: Skeleton install and ping

Step: S0 · Spec: §7 row S0

## Preconditions

- The forked DSH Desktop installed on the Windows machine; record its version or commit in the run.
- A DSH native session that exposes `install_local_workbench` (workbench standard §3.6).
- `capp-workbench-<v>.tgz` built from the PR commit with `pnpm run pack`, and its sha256 printed by that command.
- No private assets are needed.

## Script

1. Copy `capp-workbench-<v>.tgz` to the Windows machine. In a DSH native session, ask the agent to install it with `install_local_workbench` → `application` is `applied` or `restart-required`.
2. Restart Harness (top banner "Restart now" or Harness → Restart Harness) → no plugin recovery screen appears.
3. Sidebar workbench switcher → "CAPP" is listed. Workbench management → Installed shows it marked "Local".
4. Open CAPP → the panel shows "Server: ok" (the panel's `GET /api/capp/ping` check). The toolbar sits correctly with the sidebar expanded and collapsed.
5. Start a new session in the CAPP workbench and ask "call capp_ping" → the tool card shows `{ "pong": true, … }`.
6. `dsh --profile web --dump-config` contains the `capp-workbench` row → record only the row's id; no paths.

## Pass criteria

Steps 1–5 are observed as described, using the package hash recorded in the run.
