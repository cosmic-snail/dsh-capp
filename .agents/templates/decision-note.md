# Decision topic

Status: proposed / implemented / rejected (keep exactly one, matching the folder)
Date: first proposed; add a date for each revision
Baseline: source commit and PR; say so explicitly if it isn't merged

## Problem

What lasting reason is missing from the code, spec or guides? Link the existing material and say what this note adds.

## Alternatives

The choices actually considered, their trade-offs and where they came from. Say "unknown" for history nobody recorded. Don't invent alternatives to fill the template.

## Decision

Proposed: the choice to make and the condition for accepting it. Implemented: the choice made and its evidence. Rejected: why, and what would make it worth reconsidering. Rewrite this section when the status changes.

## Cost and limits

What it costs, when it stops applying, which negative guarantees it keeps. Link notes it replaces in whole or in part.

## Evidence and gaps

Link commits, spec sections or gate records, and name the platform and scope actually verified. Separate plan from result. After implementation, replace pending acceptance wording with the actual evidence; don't paste test output.
