# G0: Skeleton install and ping

Step: S0 · Spec: §7 row S0

## Preconditions

- DSH Desktop v0.13.2 on the Windows machine.
- `capp-workbench-<v>.tgz` built from the PR commit with `pnpm run pack`, and its sha256 printed by that command.
- `DEEPSEEK_API_KEY` in the user environment.
- A fresh development `DSH_HOME` for part A.
- No private assets are needed.

## Script

Part A runs on the command line: the agent runs it over a shell on the Windows machine with `scripts/dsh-cli.cmd`.

- **A1.** `dsh-cli plugin --profile headless add <absolute path to the .tgz>` → exit 0.
- **A2.** `dsh-cli --profile headless --dump-config` → the output contains an `id: capp-workbench` row; record only the id.
- **A3.** `dsh-cli --profile headless --json "Call the capp_ping tool once and report its result."` → the run events contain a `capp_ping` call whose result is `{"pong":true,"version":"<v>"}`; record the model id.
- **A4.** `dsh-cli plugin --profile web add <absolute path to the .tgz>`, then `dsh-cli web --no-open --host 127.0.0.1 --port <free port>` → after authenticating with the printed launch URL, `GET /api/capp/ping` returns `{"ok":true}` and `GET /api/capp/ping/x` returns 404 (exact-path routing, spec §4.5). Stop that server afterwards.

Part B is the DSH Desktop UI — a human, the only UI steps:

- **B1.** In a DSH Desktop native session, ask the agent to install the same `.tgz` with `install_local_workbench` → `application` is `applied` or `restart-required`; restart Harness if asked.
- **B2.** Sidebar workbench switcher → "CAPP" is listed, marked "Local" under Workbench management → Installed; open it → the panel shows "Server: ok".

## Pass criteria

A1–A4 and B1–B2 observed as described for the same package hash. Part A alone is recorded as `partial`.
