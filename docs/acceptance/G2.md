# G2: Step parse in a real session

Step: S2 · Spec: §7 row S2

## Preconditions

- `capp-step` packed and installed into the DSH Desktop web profile on the Windows machine, with local config pointing at the synced assets (`nx-extractor`, `nx-analyzer`, `nx-step-settings`, `journalRunner`, `pythonPath`, `nxRoot`).
- `capp-workbench` (S0) installed in the same profile.
- The torus STEP (`torus-step` asset) copied into the session workspace.

## Script

1. Install `capp-step` → a fresh session sees `step_parse`; restart Harness only if the install reports `restart-required`.
2. In the session, put the torus STEP in the workspace and ask "Parse this part" → `step_parse` runs (with an approval prompt if S-PERM required one) and `capp/<job>/part.json` exists.
3. The human checks the feature list against the torus: outer cylinder, inner bore, end faces — record counts by type.
4. Ask it to parse a path that doesn't exist → a clear one-line error and no job directory created.

## Pass criteria

`part.json` validates as `capp.part/v0`, its feature types/counts match what the user expects of the torus, and the bad-path case errors cleanly without leaving a job dir. S-PERM outcome (sandbox-confined vs `approveEscalation`) is recorded in spec §8.
